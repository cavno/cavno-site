先保住入口，再限制出口

以可用的 IPv4 SSH 会话与 Lish Console 为安全绳，依次完成云防火墙、系统内核、即时验证、重启复验与故障恢复。

01Cloud Firewall→02第二路 SSH→03Ubuntu sysctl→04重启与恢复

目标：禁止 Linode 的 IPv6 入站、出站和 Ubuntu 系统 IPv6，同时保留 FinalShell/SSH 的 IPv4 访问。

01一、操作前准备

  1. 登录 Linode Cloud Manager，确认可以打开该主机的 Lish Console。
  2. 保持当前 SSH 会话不要关闭。
  3. 在 Linode Cloud Manager 中确认主机的公网 IPv4 地址。
  4. 在 FinalShell 中把主机地址直接填写为该公网 IPv4，不要填写可能解析出 AAAA 记录的域名。
  5. 如果 SSH 端口不是 22，下文所有 22 均替换为实际端口。

02二、配置 Linode Cloud Firewall

进入：

Cloud Manager → Firewalls → 选择已绑定该 Linode 或其 Public Interface 的 Firewall → Rules

1. Inbound 最终配置

默认策略：

只保留以下必要规则：

顺序LabelProtocolPortsSourcesAction
1allow-ssh-ipv4TCP22All IPv4ACCEPT

要求：

  • 不添加 IPv6 来源。
  • 不添加 UDP 入站规则。
  • 如果已有允许 SSH 的 IPv6 规则，删除或禁用。
  • 如果确认本地公网 IPv4 长期固定，可在完成全部验证后把 All IPv4 改为 你的公网IPv4/32。

2. Outbound 最终配置

默认策略：

把以下四条规则放在所有 Outbound 规则的最上方：

顺序LabelProtocolPortsDestinationsAction
1block-ipv6-tcpTCPAll PortsAll IPv6DROP
2block-ipv6-udpUDPAll PortsAll IPv6DROP
3block-ipv6-icmpICMP不填写All IPv6DROP
4block-ipv6-ipencapIPENCAP不填写All IPv6DROP

要求：

  • 删除或下移位于这四条规则之前、且会允许 IPv6 的冲突规则。
  • 确认 Firewall 状态为 Enabled。
  • 确认 Firewall 已绑定到目标 Linode；如果该主机使用 Linode Interfaces，确认绑定到对应的 Public Interface。
  • 点击 Save Changes。

06六、防止 SSH 被锁死

  1. 先配置并保存 Cloud Firewall 的 IPv4 SSH 入站规则，再禁用 Ubuntu IPv6。
  2. 全程保留一个已连接的 SSH 会话，并用第二个窗口测试新连接。
  3. FinalShell 使用公网 IPv4，不使用域名，不使用 IPv6 地址。
  4. 未确认本地公网 IPv4固定前，SSH 来源保持 All IPv4。
  5. 不要把 Inbound Policy 设为 DROP 后却不配置 TCP 22 / IPv4 / ACCEPT。
  6. 不要把 Outbound Policy 设为 DROP，除非已经另外建立完整的 IPv4 放行规则。
  7. 应用配置前确认 Lish Console 可用。
