双层阻断，完整验收

先以 Cloud Firewall 阻断 IPv6，再由 sysctl 与 systemd-networkd 固化 IPv4-only；全过程保留第二路 SSH、Lish Console、备份和回滚。

01Cloud Firewall→02备份与双 SSH→03sysctl + networkd→04浏览器与重启验收

目标：禁止 Linode 的 IPv6 入站、出站和 Ubuntu 系统 IPv6，同时保留 FinalShell/SSH 的 IPv4 访问，并确保代理浏览器继续通过 VPS 公网 IPv4 正常访问互联网。

01一、实施目标与边界

最终状态应同时满足：

  • Linode Cloud Firewall 不接受 IPv6 入站，也不允许 IPv6 出站。
  • Ubuntu 的 all、default、lo 和 eth0 均禁用 IPv6。
  • eth0 不再通过 Router Advertisement 或自动配置取得 IPv6。
  • SSH 只通过 VPS 公网 IPv4 连接，端口保持实际 SSH 端口。
  • VPS 的 IPv4 地址、IPv4 默认路由和 systemd-networkd 保持正常。
  • 代理浏览器出口显示 VPS 公网 IPv4，不出现可用公网 IPv6，也不暴露本地真实公网 IP。

本文默认 SSH 端口为 22。如果实际端口不是 22，下文所有 22 均替换为实际端口。

02二、操作前建立安全绳

  1. 登录 Linode Cloud Manager，确认可以打开该主机的 Lish Console。
  2. 保持当前 FinalShell/SSH 会话不要关闭。
  3. 在 Linode Cloud Manager 中确认 VPS 的公网 IPv4 地址。
  4. 在 FinalShell 中直接填写该公网 IPv4，不使用可能解析出 AAAA 记录的域名，也不使用 IPv6 地址。
  5. 再打开一个 FinalShell 窗口，使用 VPS 公网 IPv4 登录。
  6. 两个 FinalShell 窗口都能登录后再继续。

09九、关闭 VPS 的 Network Helper

只有在 Cloud Firewall、Ubuntu 即时验证、第二路 SSH 和代理浏览器全部通过后，才执行本节。

1. 使用 Linode Interfaces

  1. 保持 Lish Console 打开。
  2. 在 Cloud Manager 关闭 VPS。
  3. 打开：VPS → Network → Interface Settings。
  4. 关闭 Enable Network Helper。
  5. 点击 Save。
  6. 启动 VPS。

2. 使用 Legacy Configuration Profile

  1. 打开：VPS → Configurations → Edit。
  2. 找到 Filesystem/Boot Helpers。
  3. 关闭 Auto-configure networking。
  4. 点击 Save Changes。
  5. 重启 VPS。

只关闭当前 VPS 自己的 Network Helper，不修改账户全局设置。

11十一、防止 SSH 被锁死的全过程规则

  1. 先保存 Cloud Firewall 的 IPv4 SSH 入站规则，再修改 Ubuntu。
  2. 全程保留一个已连接的 SSH 会话，并用第二个窗口测试新连接。
  3. FinalShell 直接使用 VPS 公网 IPv4，不使用域名或 IPv6 地址。
  4. 未确认本地公网 IPv4 固定前，SSH 来源保持 All IPv4。
  5. 不要把 Inbound Policy 设为 DROP 后却不配置 TCP 22 / IPv4 / ACCEPT。
  6. 不要把 Outbound Policy 设为 DROP，除非已建立完整的 IPv4 放行规则。
  7. 不要通过 SSH 执行 networkctl reconfigure eth0。
  8. 应用配置和重启前确认 Lish Console 可用，并记住备份目录。
